# Claude Code 指示書（フェーズ別プロンプト集） v0.2

使い方: 各フェーズの「プロンプト」を Claude Code に貼る → 「完了条件」を確認 → コミット → `/clear` → 次へ。

---

## フェーズ0: 準備（Windows・手作業）

1. Node.js LTS（`winget install OpenJS.NodeJS.LTS`）、Python 3.12、Git、GitHub CLI（`winget install GitHub.cli` → `gh auth login`）
2. 作業フォルダを作り Claude Code を起動
   ```
   mkdir D:\project_claude\komapal-shogi && cd /d D:\project_claude\komapal-shogi
   claude
   ```
3. 次のファイルは配置済み: `CLAUDE.md`（直下）、`docs/`（設計書・指示書・アバター一覧画像）、`public/avatars/`（アバター8体と manifest.json）、`tools/make_avatars.py`（アバター生成）

---

## フェーズ1: 土台とルール

```
docs/設計書.md と CLAUDE.md を読んでください。フェーズ1を実装します。

1. Vite + TypeScript（strict）のプロジェクトを設計書11章の構成で作成。Vitest、ESLint、Prettier も設定
2. src/rules/: shogiops を使ったルール層
   - SFEN 読み書き、合法手一覧（駒ごと・打ちごと）、指す、王手判定、詰み判定
   - shogiops に無い/不足する場合は自作: 千日手（4回同一局面、連続王手の千日手は反則負け）、
     入玉宣言27点法、反則理由の判定（二歩・打ち歩詰め・行き所のない駒・王手放置）
     ※反則理由は「なぜ指せないか」を子どもに説明するために使う
   - notation.ts: USI → 日本語（▲7六歩、△同銀、成/不成、打、右/左/上/引/寄/直）
   - kif.ts: KIF 形式の出力・読込
3. src/game/session.ts: 履歴スタック、待った（無制限）、進む、待った回数
4. tests/: 設計書3章の全ルール、日本語表記、待った→進むで局面一致
5. tools/rules_crosscheck.py: Python の cshogi でランダム局面1万件を作り SFEN と合法手を JSON 出力。
   Vitest 側でその JSON を読み、TypeScript の合法手と完全一致するか検証するテストを作る

まだ画面と AI は作らないでください。最後に npm test の結果を報告してください。
```

**完了条件**: `npm test` 全合格、cshogi 照合で不一致 0。

## フェーズ2: 盤面 UI（子ども向け操作）

```
フェーズ2: 画面を作ります。設計書7章・8章に従ってください。

1. SVG の 9×9 盤（木目調、星、筋・段の数字）。駒は SVG 生成（五角形＋漢字、成駒は赤字、相手駒は180°回転）
2. 駒の面に「動ける方向の点」ガイド（設定でON/OFF、既定ON）
3. タップでつまむ → 動ける升が光る → 升タップで移動。成れる時は「なる/ならない」を
   駒の絵付きで選ぶダイアログ。強制成りは自動
4. 持ち駒（自分=右下、相手=左上、種類別・枚数）タップ → 打てる升が光る → 打つ
5. お手付き取消: つまんだ駒の再タップ・盤外タップ・Escで解除
6. 指せない升をタップしたら反則の理由をやさしい言葉で表示（例「にふ（二歩）だよ…」）
7. 王手時: 王の升を赤く点滅＋「王さまがねらわれているよ！」
8. 下部ボタン: まった / すすむ / こうさん / はんてん / あたらしく / せってい（大きめ、44px以上）
9. 棋譜一覧（日本語）
10. src/ui/furigana.ts: 漢字にルビを付けるヘルパー。全UI文言をこれで表示（設定でON/OFF）
11. レスポンシブ（PC横、タブレット縦横、スマホ縦）
12. 動作確認用に「2人で対戦」モード（CPU無し）を用意

合法手判定は必ず src/rules を使うこと。
```

**完了条件**: スマホ・PC で 2 人対戦が 1 局指せる。反則升で理由が出る。待った・進むが正しい。

## フェーズ3: こども AI（レベル1・2）と Web Worker

```
フェーズ3: 設計書5章のレベル1・2を作ります。

1. src/ai/worker.ts: AI 用 Web Worker。UI とは postMessage でやり取り（choose / analyze / stop）
2. src/ai/kids-ai.ts: レベル1「ひよこ」・2「こいぬ」。パラメータは src/ai/levels.ts に集約
3. 人が指したら、先に画面へ反映 →「かんがえちゅう…」表示 → 最低0.6秒後に CPU の手をアニメーションで指す
4. 新規対局ダイアログ: レベル（名前・アイコン・説明つき）、先手/後手/ランダム、モード
5. tests/selfplay.ts（npm run selfplay）: Node 上で CPU 同士を対戦させ、反則チェックと勝率を集計
   L1 vs ランダム、L2 vs L1 を各50局実行して結果を報告
```

**完了条件**: 反則 0、L2 が L1 に 8 割以上勝つ。子どもが L1 に勝てる。

## フェーズ4: やねうら王 WebAssembly 版（レベル3〜5）

```
フェーズ4: やねうら王の WebAssembly 版を組み込みます。

1. 評価関数不要の「駒得（material）版」の WebAssembly ビルドを使う（npm の @mizarjp/yaneuraou.material
   など。まず候補パッケージのライセンス・使い方・最終更新を調べて報告し、私の了承を得てから導入）
2. src/ai/engine.ts: Worker 内で USI コマンド（usi/isready/position/go/stop、MultiPV、nodes、byoyomi）を扱う。
   読み込みは対局画面表示の後に裏で行い、盤の表示を待たせない
3. public/coi-serviceworker.js を導入し、GitHub Pages でもクロスオリジン分離になるようにする。
   外部フォント等を読み込んでいないか確認
4. レベル3〜5を設計書5章で実装（levels.ts）。端末が遅い場合は L5 の思考時間を自動調整
5. エンジンが使えない場合（非対応ブラウザ・読込失敗）は src/ai/alphabeta.ts（自作αβ、深さ3〜4）に切替し、
   「かんたんモードで動いています」と表示
6. CPU 投了（L3以上、評価値-3000以下が2手続いたら）
7. 自己対局で L3>L2, L4>L3, L5>L4 を確認（各20局）
```

**完了条件**: `npm run build && npm run preview` で L5 が動く。エンジンを無効化しても遊べる。

## フェーズ6: サポートモード

```
フェーズ6: 設計書6.2のサポートモード。

1. src/analysis/candidates.ts: MultiPV=3 で候補3手、評価値・勝率・読み筋（日本語）
2. おすすめ度★（最善との差 50点以内★★★/200点以内★★/それ以外★）と指した後の勝率
3. src/analysis/explain.ts: 詰み・王手・駒得・成り・りょうどりのねらい・守り・受けを判定し、
   子ども向けのやさしい理由文（ふりがな付き）を生成。代表局面ごとの期待文をテスト
4. マニュアル/サポート切替（対局中も可）。カード1回タップ=盤に矢印、2回目=その手を指す
5. 段階ヒント設定（ヒント1: 動かす駒だけ光る → ヒント2: 手を全部見せる）
6. 悪手アラート（勝率20%以上低下で「いまの手、あぶないかも。まったする？」）
```

**完了条件**: 候補 3 手と理由が出て、内容が局面と合っている。

